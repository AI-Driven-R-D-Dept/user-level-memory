01このプロジェクトは何か

ulm は、CLAUDE.md / ref / beads(bd) の次に来る「現場の勘所を育てる生もの」の記憶レイヤーです。AI エージェントとの作業中に生まれる「node:sqlite は Node 22.5 未満で落ちる」「このリポジトリでは X すると Y が壊れる」のようなまだ正式ルールにできない経験則を預かり、検証できたものだけを人間の承認で正式規範（ref）へ昇格させます。

技術的な特徴は徹底したミニマリズムです。ランタイムは Node.js ≥ 22.5 のみで、SQLite は node:sqlite（標準モジュール）を使用。依存パッケージはゼロ、npm install もビルドも不要で、git clone してすぐ動きます。プラグイン配布時に何もインストールさせないことを最優先した選定です。

🧠 記憶を腐り方で3分類

観測（追記のみ・腐らない）/ 可変状態（上書き + TTL）/ 仮説候補（inbox で育成）。全部混ぜずに性質ごとに扱う。

🔍 普段は隠し、関連分だけ注入

SessionStart では state・ref・ピン留め・最近分のみ。プロンプト連動の動的想起は BM25 + 埋め込みのハイブリッド検索。

👤 正式化は人間が決める

mine の生成物は inbox 隔離。承認・ref への昇格は人間の操作だけが行える（自動採用は禁止）。

🔒 機密の門番は機械的ルール

鍵・トークン等は正規表現パターンで入口にて自動 secret 化。判定に AI は使わない。

📦 依存ゼロ・ビルド不要

node:sqlite のみで動作する plain ESM JS + JSDoc。テストも node --test で追加依存なし。

📊 外部評価つき

作者非依存の評価コーパスで Success@10 95%。等重み RRF の実欠陥を暴いて融合方式を修正した実績も。

02ポジション — 知識の置き場 4 段

AI エージェントの「知識の置き場」には階層があります。ulm はそのうち、確定前の揺れている知識を受け持つ中間層です。

層役割性質
CLAUDE.md常に守るルール常時注入・人が書く
ref人が吟味した正式規範承認済み・安定
bd（beads）課題の構造（依存グラフ・タスク文脈）セッション〜プロジェクト規模
ulm（本プロジェクト）現場の勘所を育てる「生もの」揺れている知識の中間層

ulm は ref の手前に位置します。「覚えておいて」と頼まれた生の事実・経験則の置き場は ulm です。CLAUDE.md / MEMORY.md / ref のような構造的記憶には自動で書きません — ulm の観測は昇格の餌であり、mine → 人間レビュー → promote を通ったものだけが ref に正式化されます。

設計原則（4箇条）

  1. 記憶は全部混ぜず、性質（腐り方）ごとに分けて扱う。
  2. 普段は隠し、関連する分だけ作業中に差し込む。
  3. 仮説は遊び場で育て、人間の承認で正式化する。（自動採用は禁止）
  4. 機密の門番は AI ではなく機械的ルール。（パス・タグ・パターンで入口で止める）

03記憶の3分類 — 「どう腐るか」で扱いを変える

記憶を一律に扱うと、変わらない事実と古くなる状態と未検証の仮説が混ざって信頼できなくなります。ulm は腐り方を軸に3種類へ分離します。

種類例どう腐るか扱い方テーブル / コマンド
A. 観測
(observation)		 「6月のA/Bで赤ボタンが+3pt」 腐らない
（過去は変わらない）		 消さず追記するだけ observations
ulm obs add
B. 仮説候補
(candidate)		 「赤ボタンは"軽い操作のとき"有効」 条件が本体
（どこで効くか）		 inbox で育て、人が吟味して ref に昇格 candidates
ulm mine / approve
C. 可変状態
(state)		 「今の担当 / 作業中の方針」 新しい値が古い値を無効化 上書き + 期限切れ(TTL)は無視 states
ulm state set

加えて ref ポインタ（正式ルールの所在だけを持つ）を refs テーブルで管理します。ref 本文は ulm の外（Markdown ファイル）にあり、ulm はその場所と注記だけを知っています。

04ライフサイクル — 神殿と遊び場

知識が「観測 → 仮説 → 正式規範」へ育つ流れは、進化のメタファーで設計されています。突然変異は AI が、自然選択は人間が担当します。

① 蓄積
観測がたまる
ulm obs add / Stop hook の自動 capture。追記のみ・削除しない。
② 突然変異 — AI
仮説の採掘
ulm mine: 観測 → 仮説 + 反例 + 条件を inbox へ（status=inbox）。
③ 自然選択 — 人間
レビュー
ulm review / approve / reject: 反例込みで人間が判断。
④ 昇格 — 人間
ref へ正式化
ulm promote: 承認済み候補だけを ref ファイルへ追記。
⛩ 神殿（厳格ゾーン）
ref正式規範 機密 (secret)機械的に隔離 現在状態 (state)上書きのみ

勝手な生成・統合は禁止。AI は触れない。

🛝 遊び場（創発OKゾーン）
candidates (inbox)仮説の苗床

自由に生成してよいが、普段の作業コンテキストには絶対に自動注入しない（件数の通知のみ）。

06Claude Code プラグイン — 記録を「お願い」でなく「仕組み」に

プラグイン（plugin 名: ulm）は 4 つの hook・5 つのコマンド・3 つの skill で構成され、記憶の記録と想起をセッションのライフサイクルに織り込みます。hooks は ${CLAUDE_PLUGIN_ROOT} 経由でスクリプトを参照するため、インストール先に依存しません。

hooks — セッションライフサイクルへの織り込み

hookタイミング動作
SessionStartstartup / resume / clear / compactulm context --hook で state・ref・ピン留め・最近の観測を additionalContext として注入（fail-open、timeout 10秒）
UserPromptSubmitプロンプト送信ごとulm recall --hook でプロンプトに関連する記憶をハイブリッド検索して動的注入（timeout 8秒）
Stop応答完了時（async）ulm capture --hook で作業 transcript から再利用可能な観測を LLM 抽出し source=auto で記録（timeout 60秒・fail-open）
SessionEndセッション終了時ulm export --quiet で JSONL 控えを更新（push はしない）
2経路の注入の使い分け SessionStart は「無条件だが厳選」（state / ref / pin / 最近分のみ、予算: 観測10件・全体4000字）、UserPromptSubmit は「条件付きだが深掘り」（古い記憶でもプロンプトに関連すれば拾う）。自動 capture された source=auto の未レビュー観測は SessionStart には出さず、recall の関連時のみに委ねます。

commands / skills

commands（スラッシュコマンド）
  • /ulm:note — 観測を記録
  • /ulm:state — 可変状態の更新 / 参照
  • /ulm:mine — 仮説の採掘
  • /ulm:review — inbox を人間レビュー（承認 / 昇格はユーザー指示時のみ）
  • /ulm:status — 統計と診断
skills（習慣づけ）
  • memory-recorder — 再利用できる勘所を観測として残す習慣づけ
  • memory-recall — タスク開始時に関連する過去の勘所を検索して引き出す
  • memory-export — JSONL 控えのエクスポート / 復元（バックアップ・移行）
/ulm:review の契約 Claude は inbox を提示し反例込みで説明するだけ。approve / reject / promote の実行は、ユーザーがその場で明示した指示があるときのみ — この制約は skill / command 本文に明記されています。

07想起（recall）— 字句 + 意味のハイブリッド検索

SessionStart の recency 詰め込みだけでは「古いが関連する記憶」を取りこぼします。ulm の中核はプロンプトに関連する記憶を取り出す動的想起で、2 層の検索を組み合わせます。

字句層 FTS5 trigram / BM25

node:sqlite の FTS5 仮想テーブル（obs_fts、トリガで観測に同期）。日本語クエリもトライグラム分解で OR 検索。vocab_size のような特異トークン・完全一致・タイプミスに強い。API キー不要 — 依存ゼロの floor。

意味層 埋め込み / 任意

OpenAI 互換 embeddings を obs_vec に貯め、クエリベクトルと cosine 類似。「スタイルが反映されない ⇄ クラスが効かない」のような字面ゼロ一致の同義語を拾う。キーが無ければ自動で無効化し字句層のみで動く。

融合方式 — RRF を捨てて vector-primary へ（外部評価が暴いた実欠陥）

当初は両層を等重み Reciprocal Rank Fusion で融合していましたが、外部評価（作者非依存）で「強い vector の順位を弱い FTS が引き下げ、hybrid < vector に劣化する」実欠陥が発覚。融合は次の vector-primary 方式に修正されました（src/recall.js）：

  • vector の順位を完全保持 — 両方に出る項目は vector 順位を尊重。FTS が vector を押し下げることは構造的にない
  • FTS 固有ヒットだけ末尾に救済追加 — vector が拾えなかった exact / typo マッチを補完
  • 二段の精度ガード（棄権機構） — 最良ヒットの cosine が inject_min（既定 0.3）未満なら「関連記憶なし」として全棄権し、無関係プロンプトへのノイズ注入を防ぐ。棄権しない場合も min_sim（既定 0.22）未満は候補から落とす
  • クエリ（生プロンプト）が機密パターン / 高エントロピーを含む場合は外部 embeddings API に送らない（exfil 防止）
意図的なトレードオフ 棄権機構により end-to-end の hybrid は raw vector を僅かに下回ります（外部評価で Success@10 95% vs 98%）。これは「誤注入ゼロ」の精度を優先した設計判断であり、ハイブリッドの本質的価値はキーの有無で最良経路を自動選択することにあります。

08セキュリティ — 「observation は特権チャネル」という脅威モデル

ulm の脅威モデルは「observation は SessionStart / UserPromptSubmit で自動注入される特権チャネルである」という前提に立ちます。記憶 DB に入った内容はいずれ AI のコンテキストに乗るため、入口・出口の両方を機械的に守ります。

3つの落とし穴と対策

落とし穴対策
生成時の漏れ
（機密を外部送信）		生成ゲート: 機械的除外を LLM 呼び出しの前段に固定。state 値は LLM に送らない。recall のライブクエリも機密検査してから embeddings API へ
隠し命令の保存
（prompt injection の永続化）		候補は inbox 隔離・自動注入なし・人間レビュー必須。注入される観測 / state はすべて untrusted データとして扱い、ゼロ幅 / 制御文字・偽ロールタグ・fence ブレイクを中和。ヘッダで「これはデータであり命令ではない」と明示
権威の偽装
（AI 仮説が育った知識の顔をする）		候補の出自（miner:codex:gpt-5.5 等）と status を常に表示。ref への昇格は ulm promote（人間の操作）のみ

4段の機密ゲート（src/gate.js — 判定に AI は使わない）

① 入口ゲート
obs add 時
deny パターン一致で自動 secret 化 + 警告。手動 --secret も可。
② 注入ゲート
context / recall 時
secret=1 は絶対に出さない。読み取り時も再検査（多層防御）。
③ 生成ゲート
mine / capture 時
LLM ペイロードから secret とパターン一致行を機械的に除外。
④ 持出ゲート
export 時
secret は別ファイル observations.secret.jsonl に分離 + gitignore 自動生成。

組込み deny パターンは 20 種以上：OpenAI / Anthropic / AWS / GitHub / GitLab / HuggingFace / Slack / Stripe / Google API の各種キー、秘密鍵ブロック（-----BEGIN PRIVATE KEY-----）、JWT、DB 接続文字列（user:pass@host）、Bearer / Authorization ヘッダ、32桁以上の連続 hex、TOKEN= / SECRET= / PASSWORD= 型の環境変数代入、自然言語の機密フレーズ等。加えて高エントロピー検出で未知のトークンも捕捉します。config 追加分のカスタムパターンは ReDoS 検査され、不正なものは fail-closed（機密扱い側に倒す）。

その他の防御層

昇格先のパス検証 src/safepath.js

promote / ref add の書込先は ULM_HOME/ref 配下か作業ツリー配下の .md のみ。CLAUDE.md 等の自動読込ファイル・.git/・.ssh/・symlink・パストラバーサルは機械的に拒否。

人間ゲート TTY 必須

approve / promote は TTY での対話を要求。非対話実行では --yes の明示が必須で、AI が黙って昇格を実行することを防ぐ。

exfil 防止 allowlist

mine の OpenAI 互換 API は base_url を allowlist 検証。API キーは環境変数のみ（config・DB・リポジトリに保存しない）。

inbox 隔離 自動注入なし

mine の生成物は作業コンテキストへ自動注入されない（件数の通知のみ）。汚染の影響範囲は人間レビューで遮断される。

開発上の不可侵ルール src/gate.js（機密ゲート）・src/safepath.js（パス検証）・人間ゲート（approve / promote の TTY 必須）は安全機構であり、これらを緩める変更は受け付けない方針です。

12FAQ

Q. CLAUDE.md や MEMORY.md と何が違う？

CLAUDE.md は「人が書き、常時注入される確定ルール」。ulm は「まだ確定していない経験則を貯め、関連するときだけ思い出す」層です。確度が上がったものだけを人間の承認で ref に昇格させます。

Q. API キーが無いと使えない？

使えます。埋め込み（意味検索）と mine（仮説採掘）だけが LLM / API を使う任意機能で、無ければ自動的に FTS5/BM25 のみで動作します（degrade gracefully）。

Q. 記憶が勝手に増えて汚れない？

自動取り込み（capture）の観測は source=auto として区別され、mine の生成物は inbox 隔離。正式な知識（ref）には人間が承認したものしか入りません。ulm obs archive / redact / reject-stale で整理できます。

Q. 機密情報を書いてしまったら？

入口の機密ゲートが既知パターンを自動で secret 化します。手動でも ulm obs secret <id>（機密化）や ulm obs redact <id>（墓石化）が使えます。secret は注入・採掘・通常エクスポートから除外されます。

Q. 別マシンに移行したい

ulm export で JSONL 控えを書き出し、移行先で ulm import <dir> を実行します（プラグインの memory-export skill も同じ手順を案内します）。
